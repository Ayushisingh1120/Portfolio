01 GenAI & AI Agents

CareCRM AI — AI CRM & Customer Support Copilot

AI-powered customer support copilot integrating CRM data and knowledge bases for context-aware responses.

Repository

Built an AI-powered customer support copilot integrating CRM records and organizational knowledge bases to provide context-aware responses to complex customer queries.

  • Implemented RAG, semantic vector search, and LLM-based response generation to retrieve customer and product information while mitigating hallucinations.
  • Developed tool-calling workflows with FastAPI and CRM REST APIs to retrieve records, summarize tickets, and automate support actions.
  • Designed session memory and confidence-based human handoff triggers when query uncertainty exceeds safe thresholds.

The Challenge: Hallucination Mitigation & Trust in CRM

In enterprise customer support, false or hallucinated responses directly degrade customer trust. A simple chat LLM might promise non-existent refunds or incorrect order dates. I tackled this by decoupling knowledge retrieval into strict verified sources: ChromaDB vector search for product policy documentation, and deterministic CRM REST API endpoints for customer transactional state. Furthermore, a confidence threshold classifier evaluates response faithfulness—if confidence is insufficient, it synthesizes an incident summary and seamlessly transfers the context to human support agents.

Agentic Tool-Calling Architecture

The system operates as an asynchronous FastAPI pipeline. Incoming customer messages pass into an intent classification node with function-calling capabilities. Depending on the intent, the copilot executes tool calls against the CRM REST API (fetching order logs, ticket histories) or executes cosine similarity queries on the vector knowledge base. State is tracked via conversation memory buffers, and output responses are validated against safety and domain rules before delivery.

Core Stack

Python 3.11+, FastAPI, LLM (OpenAI / Claude API), RAG Architecture.

Vector Engine & Search

ChromaDB / Pinecone Vector Store, Sentence Embeddings, Cosine Similarity Filtering.

Integrations

CRM REST APIs, Ticket Summarization, Tool/Function Calling Workflows, Human Handoff Fallbacks.

02 RAG & Document Intelligence

EnterpriseIQ — Enterprise RAG Knowledge Assistant

Document intelligence system for querying enterprise knowledge bases using Retrieval-Augmented Generation.

Repository

Built a comprehensive document intelligence platform enabling enterprise teams to query multi-format internal repositories using Retrieval-Augmented Generation (RAG).

  • Implemented document ingestion, chunking strategies, embedding generation, semantic retrieval, and reranking to elevate context relevance.
  • Developed a FastAPI-based backend supporting multi-document search, conversational queries, and source-cited responses.
  • Evaluated response quality using relevance and faithfulness metrics to minimize hallucinations.

The Challenge: Context Fragmentation in Large PDFs

Standard chunking schemes either slice sentences midway or overload the prompt with uninformative background noise. I implemented a sliding-window recursive chunking strategy with semantic boundaries and overlap to preserve full conceptual paragraphs. To bridge the gap between initial dense retrieval and synthesis, I added a cross-encoder reranking stage that re-scores the top 10 candidate chunks down to the 3 most precise passages, ensuring the LLM is fed purely actionable information with exact page/section citations.

Two-Stage Ingestion & Retrieval Pipeline

1. Ingestion Pipeline: Parsers extract raw text from PDFs and Markdown, split them via RecursiveCharacterTextSplitter, generate dense vector embeddings via HuggingFace Sentence Transformers, and store them in FAISS/ChromaDB with metadata headers.
2. Retrieval & Generation Pipeline: User prompt -> Dense vector search -> Cross-encoder reranker -> Citation-grounded prompt compilation -> LLM generation with explicit source links.

Frameworks & Ingestion

Python, LangChain, Sentence Transformers (all-MiniLM-L6-v2), PyPDF / Unstructured.

Vector Stores & Indexing

FAISS index, ChromaDB, Cross-Encoder Reranking, Metadata Filtering.

03 Machine Learning & Deep Learning

Guardio — Credit Card Fraud Detection Pipeline

End-to-end fraud detection pipeline tackling extreme class imbalance for financial transaction classification.

Repository

Built an end-to-end fraud detection machine learning pipeline using Logistic Regression on highly imbalanced transaction data, achieving 97% overall accuracy and 92% recall on fraudulent cases.

  • Applied SMOTE (Synthetic Minority Over-sampling Technique) and feature scaling during preprocessing to strengthen rare-event classification.
  • Evaluated model using Precision-Recall curves, ROC-AUC, and Confusion Matrices to minimize costly false negatives.
  • Engineered preprocessing modules using Scikit-learn, Pandas, and NumPy to streamline live transaction batch scoring.

The Challenge: Extreme 0.17% Class Imbalance

In fraud detection, 99.8% of transactions are legitimate. A trivial baseline that flags everything as genuine achieves 99.8% accuracy but 0% fraud detection utility. To solve this, I applied SMOTE exclusively to the training split, synthesizing minority instances along k-nearest neighbor line segments while preventing data leakage into the test set. By tuning probability decision thresholds, I boosted fraud recall to 92% while maintaining high precision.

ML Data Pipeline Lifecycle

1. Ingestion & Preprocessing: Handling PCA-transformed transaction features, robust scaling of transaction amount and time deltas.
2. Resampling: SMOTE balancing on training folds.
3. Estimator: Regularized Logistic Regression with cross-validation.
4. Evaluation: Analyzing Precision-Recall trade-offs, F1-scores, and ROC-AUC metrics to ensure resilience against adversarial patterns.
